# Heirloom

## Cursor Cloud specific instructions

The dedicated Windows product is the native WinUI 3 studio (`desktop/Heirloom/`). The React app is the public/marketing/heir-token surface; owner studio on Windows lives in WinUI. Legacy PySide6 (`backend/companion_desktop/`) remains as a fallback zip only.

- Mixer volume is the **Heirloom WASAPI session**, not the system master. Native mixer: `desktop/Heirloom/Services/MixerSessionService.cs`. After changing the *legacy* PySide audio path, run `python backend/build_desktop_data.py` so that zip stays in sync.
- **Assist vs Twin:** Sit opens **Assist** (`AssistantViewModel` + `PcToolkit`) — copilot on this PC, never first-person as the owner. Twin is its own dock group (grounded sitting, likeness). `POST /api/desktop/chat` `mode=assistant` keeps PC tools; `mode=twin` strips pc_control / screen_vision / terminal. Confirm shell, type_text, sleep/shutdown/restart in-document (no MessageBox).
- **WinUI run (only if the owner asked to launch):** `dotnet run --project desktop/Heirloom/Heirloom.csproj -c Release -r win-x64 --no-launch-profile`. Do not auto-start `Heirloom.exe`, Explorer, or UAC. Publish: `dotnet publish desktop/Heirloom/Heirloom.csproj -c Release -r win-x64 -o desktop/dist/Heirloom-ready /p:WindowsPackageType=None /p:PublishTrimmed=false` (use this folder when `desktop/dist/Heirloom/Heirloom.exe` is locked). Pairing: paste device token in Settings (Credential Locker). Manifest: `GET /api/companion/winui`. Sideload zip: `GET /api/companion/winui-package`.
- Studio persistence lives at `GET/PUT /api/studio/audio`, `GET/PUT /api/studio/models`, and `GET/PUT /api/studio/compute` plus `POST /api/studio/models/provision`. **Compute target** (`local` = this PC, `network` = pick a registered companion, `server` = remote Ollama URL) is configured in `/models` via `ComputeTargetPanel` (web) and the WinUI Models document. The companion applies `audio_settings` / `model_map` / `studio_compute` from `/api/companion/poll` and reports GPU/Ollama/Whisper via `POST /api/companion/runtime` (also copied to `users.companion_runtime_probe` for routing). Provision commands include `target_device_id` so only the selected network PC runs them.
- **First-run setup** (WinUI overlay): one **Get everything ready** button. Default vault `Documents\HeirloomVault`. No tokens, no backend URL, no vendor email, no model SKUs. Downloads Whisper (`ggml-base.bin`), installs/starts Ollama if needed (Windows may UAC — user clicked the button), pulls llama3.1, and fetches the talking-picture engine when disk + NVIDIA allow. Failures are human copy with Try again. Lands on **Twin** with Talk / Record a memory / Make a likeness. Vendor coach is **Settings → Optional: copied voice guide…**, never auto-started. Reopen from Help → Getting started. `%LOCALAPPDATA%\Heirloom\settings.json` `setup_complete` / `setup_skipped` skip the overlay on launch. Optional guide still uses `GET/PUT /api/studio/first-run`, `POST .../coach/observe`. Heirloom does **not** drive vendor DOM, create third-party accounts, solve captchas, or read keys off a screenshot. Web `/setup` remains the marketing/heir key surface. **The legacy PySide zip is still baked by the live Emergent API** (`GET /api/companion/desktop-package`). Native installs use `desktop/Publish-Heirloom.ps1` / `GET /api/companion/winui-package`. Overlaying `backend/companion_desktop` onto an existing *legacy* install must keep the baked `heirloom/config.py` (token + `BACKEND_URL`). Titlebar shows `0.5.0` plus `BUILD_ID`. Emergent promote checklist: `EMERGENT_HANDOFF.md`.
- **Twin brain routing:** `backend/model_router.py` resolves STT/twin/TTS from `studio_models` + the runtime probe. Voice on the dedicated PC prefers **local faster-whisper → local Ollama** when provisioned; cloud Claude/ElevenLabs remain fallbacks. Desktop endpoints: `POST /api/desktop/brain-pack`, `POST /api/desktop/chat/local-complete`.
- `say` commands and the legacy companion script call **`POST /api/desktop/speak`** (cloned voice) before OS TTS.
- Web chrome is an Adobe-style studio shell: app menubar + icon dock + floating document window (`AppLayout`, `StudioWindow`). Per-route dropdown menus live in `frontend/src/components/studio/menuDefinitions.js`. Reusable inspector panels use `StudioPanel`, `StudioFieldRow`, `StudioTabs`, `StudioWorkspace`, and `FeatureModelPanel` under `frontend/src/components/studio/`. **Model credentials** are configured per feature in `/models` (inline key + Test), not only on `/setup/keys`. API: `PATCH /api/studio/models/{feature_id}`, `POST .../test`, `POST .../provision`.
- `CONVEX_AGENT_MODE` is unrelated to this repo. Local auth for API tests is a seeded Mongo session Bearer token (see `backend/tests/conftest.py` / `auth_testing.md`).
- Standard lint/test/run commands are in `frontend/package.json` (`yarn start`, `yarn test` if present) and `backend/` (`uvicorn server:app --host 0.0.0.0 --port 8001 --reload`, `pytest`).
